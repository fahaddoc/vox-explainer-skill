# Shots and the Remotion engine

## Engine contract

`~/vox-studio/engine/SCENES.md` is the contract every builder reads first. In short:
- Remotion 4, 1920x1080, 30 fps. One file per shot `src/scenes/Vxx.tsx` exporting `Vxx: React.FC<ShotProps>`, optional `Vxx_cues(p)` (SFX) and `Vxx_music(p)` (music dips).
- `ShotProps`: `p.w(i)` = frame where GLOBAL word i starts, relative to the shot, minus a 4-frame visual lead (so `at={p.w(i)}` lands as the word is heard). `p.we(i)` = word end. `p.dur` = shot length. Never hardcode seconds for word sync.
- Every shot keeps moving (`<Camera drift>` or continuous animation); no dead-static frame over 1.5 s. Hard cuts between shots; a shot ends mid-breath, so keep motion to its last frame.
- Deterministic only (`rand(seed)` from `lib/anim`; no `Math.random`/`Date`).
- Library: `components/` (Surface/Paper/Grain, Camera, Cutout, Doc, Icons, Motifs, SectionCard, Box, Type: KineticLine/Highlight/Stamp, WorldMap), `lib/anim` (prog, pop, envelope, lerp, track, rand, sec), `theme` (C colours, F fonts, E easings, SPRING configs, FPS/W/H).
- Look: warm paper collage, rust-orange hero object among grey ones (the recurring motif), ink black, highlighter yellow, teal sea, navy. Archival photos toned with `prep_images.py`.

## shots.json

Generated by `script/build_shots_<slug>.py`:
```json
{
  "_notes": "rules for every shot (onscreen = line's onscreen field unless spec says otherwise; never show a number the VO doesn't say; new beat every ~2.5 s; land on the word; keep the style)",
  "batches": {"B1_hook": ["V01", "V02"], "B2_problem": ["V06"]},
  "shots": [{"id": "V01", "lines": ["L01", "L02", "L03"], "src": ["S17"], "spec": "what to build, beat by beat, keyed to VO words"}]
}
```
`gen_storyboard.py` adds `from`, `to`, `w0`, `w1` (frames and global word range).

**Writing specs:** describe each beat as "on '<word>': <what happens>". Name the WHY explicitly where it applies ("this shot must make obvious that the port, not the sea, was the expensive part"). A spec that says "show stats" yields a stats slide; a spec that says "the two port bars slide together into one IN PORT bar, visibly longer than AT SEA" yields understanding.

**Shot sizing:** 3-8 s per shot; split a line into two shots when its visual changes idea. The container video had 37 shots for 52 lines. Group 4-7 shots into a batch per act (hook, problem, invention, proof, standard, world, twist+outro) so one builder agent owns one coherent stretch.

## Parallel build rules (prevent edit collisions)

- A builder writes ONLY its batch's `Vxx.tsx` files plus ONE helper file `parts/V_<batch>.tsx`.
- Read-only for builders: `components/*`, `lib/*`, `theme.ts`, `Root/Main.tsx`, `storyboard.ts`, `entries/*`, other batches' files, `tools/`. To change a shared helper, copy it into your own parts file and change the copy.
- When two batches must look identical (e.g. the bill + chips in V12 and V18 of the container video), either give one agent ownership of both shots plus a new shared parts file (`parts/V_why.tsx`), or make the cross-batch text changes yourself first, before launching the builders. Prescribe exact label strings in the prompts so batches agree.
- Reviewer agents render their **own** stills (not the builder's) and check: each element lands on its word, text is plain and spelled right, nothing clipped or overlapping, facts unchanged, transitions still flow.

## Stills, typecheck, timing

```bash
cd ~/vox-studio/engine
npx tsx ../tools/stills.ts B2_problem V12 0 w163 w175 end     # → review/V12_<frame>.jpg, ~8 s; wN = global word index inside the shot (V12 = words 163-186)
npx tsc --noEmit -p .
```
`wN` = 2 frames after global word N starts. The word table per shot is in `script/storyboard.md`. Keep each call ≤ 5 frames.

## SFX on shots

`Vxx_cues = (p) => [{at: p.w(12), name: 'whoosh_m1', gain: -8, pan: 0.2}, ...]`. Names refer to files in `audio/sfx/` or `audio/sfx/synth/`. Booms are reserved for about 5 story beats (`BOOM_OK` in `tools/build_cues.ts`); elsewhere they are auto-demoted to `hit_soft`. Give every action a small sound (paper slide, pop, stamp, clank) and a sound hook at the cut.

## Visual patterns that explained well (container video)

- Before/after split canvas with a torn-paper seam: heap of loose cargo + price card vs one box + price card, then a stamp with the % change.
- Process shown as one continuous object path: factory → truck → crane → ship → crane → truck, with a "TIMES LIFTED" counter.
- A bill with bars, where the cause rows slide together into one total bar next to the comparison bar.
- Persistent cause-and-effect stack: "FEWER WORKERS / + SHIP LEAVES SOONER / = PORT COST DOWN" with a stamp.
- Scale contrast in one frame: tiny first ship labelled "58 BOXES" next to today's giant "24,000+".
- Chapter cards stencilled on the hero object (the box), with a title that says what the chapter is about.
